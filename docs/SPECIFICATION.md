# 📖 Технічна Специфікація та Архітектура Проєкту

## 1. Загальний опис системи

Додаток **"Трекер Виплат ЗСУ"** розроблено для забезпечення персонального фінансового та оперативного обліку службової діяльності військовослужбовців ЗСУ. 

Головні пріоритети:
- **Конфіденційність (Data Sovereignty)**: Дані не залишають пристрій користувача. Жодних аналітик, метрик, зовнішніх серверів.
- **Відзовостійкість та Автономність**: Можливість повноцінно працювати в режимі "Авіарежим" або при відсутності мережевого зв'язку.
- **Гнучкість тарифів**: Можливість змінювати місячну базу та денні тарифні сітки у разі законодавчих змін.

## 2. Структура Даних (Data Models)

### 2.1 День Служби (`DayRecord`)
```typescript
interface DayRecord {
  date: string; // Формат "YYYY-MM-DD"
  typeId: string; // ID типу виплати (напр. 'combat_100k', 'duty_30k', 'base', 'vacation', 'sick_leave')
  customRate?: number; // Якщо вибрано кастомний тариф
  notes?: string; // Примітка (номер БР, наказ, сектор, бойова позиція)
  orderNumber?: string; // Номер Бойового Розпорядження / Наказу
  isPaidOut?: boolean; // Позначка чи закритий день фактичною виплатою
}
```

### 2.2 Тип Дня / Виплати (`PayoutCategory`)
```typescript
interface PayoutCategory {
  id: string;
  name: string;
  shortName: string;
  monthlyAmount: number; // Наприклад 100000, 50000, 30000
  dailyRate: number; // Розрахункова денна ставка (monthlyAmount / дні_місяця або фіксована)
  color: string; // Tailwind колір для підсвічування в календарі
  countsTowards70k: boolean; // Чи зараховується цей день до норми 30 днів для виплати 70 000 грн
  description: string;
}
```

### 2.3 Профіль Налаштувань Грошового Забезпечення (`FinancialProfile`)
```typescript
interface FinancialProfile {
  baseMonthlySalary: number; // Основне Грошове Забезпечення (ОГЗ) на місяць (посадовий оклад + звання + вислуга)
  rank: string; // Звання (опціонально)
  position: string; // Посада (опціонально)
  customCategories: PayoutCategory[]; // Власні створені типи днів
}
```

### 2.4 Запис Фактично Отриманих Виплат (`PaymentTransaction`)
```typescript
interface PaymentTransaction {
  id: string;
  date: string; // Дата фактичного зарахування (YYYY-MM-DD)
  monthTarget: string; // За який місяць виплата (YYYY-MM)
  amount: number; // Сума гривень
  category: 'base_salary' | 'additional_reward' | 'bonus_70k' | 'wellness' | 'material_help' | 'other';
  notes?: string; // Коментар (наприклад, "Аванс" або "Бойові за вересень")
}
```

## 3. Математика та Алгоритми Розрахунків

### 3.1 Розрахунок Денної Ставки Додаткової Винагороди
У ЗСУ додаткова винагорода (100к, 50к, 30к) нараховується пропорційно дням виконання завдань у розрахунку на календарний місяць.
- $\text{Ставка за 1 день} = \frac{\text{Місячна норма (напр. 100 000 грн)}}{\text{Кількість днів у даному місяці}}$
  - Для місяця з 30 днів (напр. вересень): $100\,000 / 30 = 3\,333{,}33 \text{ грн/день}$
  - Для місяця з 31 дня (напр. жовтень): $100\,000 / 31 = 3\,225{,}80 \text{ грн/день}$
  - Для лютого (28/29 днів): $100\,000 / 28 = 3\,571{,}42 \text{ грн/день}$

> **Примітка**: Додаток підтримує як точний розрахунок за дні конкретного місяця, так і можливість задати фіксовану денну суму вручну.

### 3.2 Лічильник 70 000 грн
- Кожен день із прапорцем `countsTowards70k = true` додає +1 до накопичувального лічильника.
- При досягненні 30 днів системний індикатор сигналізує про виникнення права на виплату одноразової винагороди 70 000 грн та пропонує зафіксувати це в обліку.

### 3.3 Алгоритм Звірки (Reconciliation)
Для кожного місяця ($M$):
$$\text{Очікувано}(M) = \text{ОГЗ} + \sum_{d \in M} \text{Ставка}(d) + \text{Разові Виплати}(M)$$
$$\text{Отримано}(M) = \sum \text{Транзакції}(M)$$
$$\text{Баланс}(M) = \text{Отримано}(M) - \text{Очікувано}(M)$$

- Якщо $\text{Баланс}(M) = 0$: Статус **Виплачено повністю**.
- Якщо $\text{Баланс}(M) < 0$: Статус **Недоплата** ($\text{Абсолютна сума боргу}$).
- Якщо $\text{Баланс}(M) > 0$: Статус **Переплата / Позачерговий аванс**.

## 4. Інтерфейсні Модулі (UI Design)

1. **Головна панель (Dashboard)**:
   - Картки швидкого стану за поточний місяць.
   - Прогрес-бар накопичення 70к.
   - Загальний фінансовий баланс (борг частині / борг частини вам).
2. **Календарний вид (Calendar View)**:
   - Сітка місяця.
   - Інструмент штампа / швидкого виділення кількох днів.
   - Індикатор заповненості кожного дня.
3. **Модуль Транзакцій та Звірки**:
   - Форма внесення банківського зарахування.
   - Журнал виплат по місяцях з колірними статусами.
4. **Налаштування та Експорт**:
   - Налаштування ОГЗ та категорій.
   - Резервне копіювання у JSON.
   - Імпорт даних з файлу.

## 5. Безпека даних

- Усі дані зберігаються в `IndexedDB` через захищену обгортку (`idb` / `dexie.js`).
- Відсутність зовнішніх скриптів аналітики (Google Analytics, Sentry тощо).
- Функціонал експорту дозволяє створити резервний файл з можливістю шифрування за допомогою AES-GCM (пароль вказує користувач).
